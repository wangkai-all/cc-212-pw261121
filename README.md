# 集装箱堆存费用分析（纯前端，零依赖、零构建）

按集装箱的**实际占用区间**还原堆存费用。导入进场、出场、移箱、箱型变化事件和免费期协议，
系统逐段计算堆存费，支持暂停计费、部分减免、补录出场的全程追溯；数据冲突进入「待处理」，
**绝不自动拼接数据里不存在的占用时段**。

## 运行

无需安装任何依赖、无需构建。任选一种方式：

```bash
# 方式一：静态服务器（推荐，ESM + fetch 标准用法）
python3 -m http.server 8000
# 浏览器打开 http://localhost:8000

# 方式二：Node 内置
npx serve .
```

打开页面后会自动加载 `data/` 下的虚构样例。所有计算在浏览器本地完成，不连接任何港口系统或后端。

## 两种计费口径（严格分开，绝不混用）

每个协议版本声明且仅声明一种 `billing_basis`。同一占用段生命周期内若协议把口径从一种改成另一种，
系统不会各算一半，而是把整段**费用挂起**并在「待处理」生成口径冲突，由人工裁定全段统一按哪种口径重算。

### 自然日 `calendar_day`

- 进场当日计为第 1 个自然日；**出场当日不计费**；同日进出按 0 个自然日处理。
- 暂停区间覆盖到的自然日整段剔除：不计费，也**不消耗免费期**，免费期在暂停结束后顺延。
- 免费期与费率档位按「当日适用的协议版本」各自起算：占用期间协议修订，新版本重新授予免费期、
  档位从第 1 档重新累计；旧版本已经使用的免费期不回滚。
- 当日费率取**当日日首（UTC 00:00）的箱型**；一天之内的箱型变化从次日起影响费率。
- 每个自然日的费用归属该自然日所在月份。

### 满 24 小时 `rolling_24h`

- 从进场时刻起每 24 小时切一块，**凑满一整块才产生一个计费单位**；不足 24 小时的零头不计费
  （仍在场的箱子同理：预提只认已经走完的整块，未走完的时间绝不提前出账）。
- 免费期 = 若干个完整 24 小时块；暂停覆盖的整块剔除、计费时钟顺延、不消耗免费期。
- 费用在该 24 小时块「走完的时刻」确认，并按该完成时刻归属月份。
- 块归属以块起始时刻适用的协议版本为准；跨协议版本时免费期与档位同样重新起算。

> 全部时间戳按 **UTC** 解析与切日（样例数据均带 `Z`），避免时区让同一份数据在不同机器算出不同结果。

## 免费期、档位与协议修订

- 协议支持 `global`（全局，`scope_value: "*"`）与 `container`（箱专属）；箱专属优先，否则回落全局。
- 费率按箱型单列（如 `20GP` / `40GP`），未单列的箱型回落到 `type: "*"` 的通用费率。
- 费率按计费单位序号分档（`from_day`），跨月不影响档位，仅影响金额归属月份。
- 「协议版本」页展示每个协议的全部版本、字段级修订（口径 / 免费期 / 费率 / 适用范围）；
  单箱详情对已关闭占用段给出**修订前后金额差额**。口径不同的相邻版本不自动算差额，避免变相混算。

## 冲突与可追溯性

| 冲突 | 触发 | 处理选项 |
|---|---|---|
| 重复进场 `dup_gate_in` | 上一次进场尚未出场又来一次进场 | 忽略（保留原占用）/ 以本次进场替换开始时间（原进场留痕） |
| 先出后进 `orphan_gate_out` | 出场找不到对应进场 | 忽略 / 登记为补录占位（待人工补进场，补填前费用挂起） |
| 口径切换 `basis_switch` | 占用期间协议改了计费口径 | 全段统一按自然日 / 满24小时重算 |
| 区间外事件（预警） | 移箱或箱型变化不落在任何占用段 | 知悉忽略，不参与计费 |
| 事件编号重复（预警） | `event_id` 重复 | 留痕 |

- 冲突 id 是**确定性**的（基于类型+箱号+事件），重算后人工裁定不会失效。
- 补录出场：`recorded_at` 晚于 `event_time` 时，时间线和账单上保留「事件发生 / 系统登记」两个时刻。
- 所有导入、裁定、撤销都写入操作审计日志。
- 仍在场的占用按固定的样例当前时刻（`2026-11-18 12:00 UTC`）**预提**，UI 明确标注
  「在场预提，非最终账单」，且不进入「最终应收」KPI。

## 数据格式

### 事件 `data/events.csv`

`event_id, container_no, event_type, event_time, location, new_type, initial_type, recorded_at, note`

- `event_type`：`gate_in` 进场 / `gate_out` 出场 / `move` 移箱 / `type_change` 箱型变化
- 进场事件用 `initial_type` 登记初始箱型；箱型变化事件用 `new_type` 登记目标箱型
- `recorded_at` 留空表示实时登记；填写且晚于 `event_time` 即视为补录
- 时间支持 ISO 8601，建议一律带 `Z`（UTC）

### 费用调整 `data/adjustments.csv`

`adj_id, container_no, adj_type, start_time, end_time, container_type, discount_pct, reason, note`

- `adj_type`：`pause` 暂停计费 / `waiver` 部分减免
- `waiver` 需给 `discount_pct`（0~100）；`container_type` 留空表示对该箱所有箱型生效

### 协议 `data/agreements.json`

协议版本数组，字段含 `agreement_id` / `version` / `scope_type` / `scope_value` /
`billing_basis`（`calendar_day` 或 `rolling_24h`）/ `free_days` /
`effective_from` / `supersedes_at`（留空表示现行）/ `rates`（`type` + `from_day` + `rate`）。

## 目录结构

```

  util.js               时间/UTC/金额/CSV
  models.js             事件、调整、协议的标准化与校验
  reconstruction.js     事件流 → 占用段 + 冲突（只登记不猜测）
  agreements.js         协议匹配、口径切换检测、版本 diff

  store.js              前端状态、人工裁定、审计、CSV 导出

```

## 设计与可访问性

- 分类色板经过色盲（CVD）与正常色觉 Delta E 校验，浅色模式下对比度不足的青/黄色靠
  「2px 表面间隙 + 文字标签 + 表格视图」补救，颜色不单独承载信息。
- 状态色（正常/预警/严重/挂起）与分类色分离，状态均带图标化圆点 + 文字徽章。
- 时间线每一段都有 hover 提示，且同一信息在逐段费用依据表中完整可查（提示不构成信息门槛）。
- 跟随系统的浅色/深色主题，也可在右上角手动切换。
